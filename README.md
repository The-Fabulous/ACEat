# ACEat — подготовка к SAT

**Сайт на Vercel: [aceat.vercel.app](https://aceat.vercel.app/)**

Четыре модуля: учебники, ИИ-чат по темам SAT, архив прошлых экзаменов и авторские Challenge-экзамены.

GitHub Pages: [the-fabulous.github.io/ACEat](https://the-fabulous.github.io/ACEat/)

## Полный деплой на Vercel

Vercel запускает `app.py` как FastAPI-приложение: сайт, LangGraph-чат и PDF-эндпоинты работают на одном домене. `pyproject.toml` задаёт Python 3.12 и зависимости; `vercel.json` — пресет FastAPI и максимальную длительность запроса 300 секунд. Сборка и установка зависимостей выполняются в облаке Vercel.

При импорте `The-Fabulous/ACEat` из GitHub выберите:

- **Project Name:** `aceat` (или другое свободное название строчными буквами).
- **Root Directory:** `./`.
- **Application Preset:** `FastAPI`.
- **Build and Output Settings:** стандартные, без ручных переопределений.
- **Environment Variables:** `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `GEMMA_MODEL` — значения из своего локального `.env` Classifi/ACEat. Значения по умолчанию: `OPENAI_BASE_URL=https://llm.alem.ai/v1`, `GEMMA_MODEL=gemma4`.

После Deploy проверьте `/api/health`: ожидаются `ok: true`, `configured: true`, `runtime: "vercel"`. Затем проверьте чат, прохождение варианта SAT и PDF-вкладку книги. На домене Vercel браузер обращается к собственному `/api`, без localhost и Cloudflare-туннеля.

Оригиналы PDF скачиваются с зарегистрированных источников с проверкой SHA-256 и кэшируются в `/tmp`, доступном для записи в Vercel Functions. Кэш временный: новая функция может заново загрузить оригинал. Учебники отдаются потоком, включая HTTP Range, поэтому большой файл не превращается в один буфер ответа. HTML, CSS, JavaScript и публичные JSON выдаются по разрешённому списку; `.env`, Python-код, служебные папки и SQL не доступны как страницы сайта. `.vercelignore` и `excludeFiles` исключают локальные исходные PDF, виртуальное окружение, кэши и `.env` из деплоя.

`server.py` и `start-aceat.cmd` по-прежнему предназначены для локального запуска. Файлы `auth-config.js` и `supabase/setup.sql`, подготовленные для кабинетов, не заменяют настройку возвратного URL в Supabase: после получения постоянного адреса Vercel используйте его в Authentication → URL Configuration.

Личный кабинет доступен по `/#account`: регистрация с подтверждением почты, вход, восстановление пароля, имя и целевой балл. В Supabase → Authentication → URL Configuration для текущего продакшена указаны Site URL и Redirect URL `https://aceat.vercel.app/`. В браузер передаётся только публичный ключ из `auth-config.js`; таблицы защищены RLS из `supabase/setup.sql`.

Для каждого варианта сохраняется текущая попытка (ответы, отметки, позиция, завершение), для каждого учебника — последняя открытая подтема. Локальные записи разделены по ID аккаунта. Гостевые ответы экзаменов переносятся только кнопкой в кабинете. При сбое сети прогресс остаётся в браузере; кнопка «Синхронизировать» повторяет сохранение. История всех прошлых попыток экзаменов пока не ведётся.

## ИИ-чат: LangGraph, как в Classifi

Граф перенесён из `Classifi/tutor_graph.py` и адаптирован для SAT: определение намерения → объяснение правила (`formula`) или разбор задания (`solve`) → структурированный ответ с шагами и формулами. Один вопрос выполняет два последовательных обращения к модели. Поддерживаются Algebra, Advanced Math, Data Analysis, Geometry & Trig и Reading & Writing. На сервер передаются выбранная тема и последние восемь сообщений выбранного диалога, по 1200 символов; в сохранённой истории остаются полные вопросы и структурированные ответы.

История чата сохраняется в `aceat_chat_messages` с привязкой к `auth.users.id`. Для существующей базы один раз выполните `supabase/chat-history.sql` в SQL Editor (для новой базы всё включено в `setup.sql`). RLS разрешает чтение и добавление только владельцу; сообщения добавляются по уникальным ID с идемпотентным повтором, без перезаписи истории с другого устройства. Привилегированный ключ и изменения Python API не требуются.

В каждой теме доступен список диалогов. «Начать заново» создаёт новый диалог, сохраняя предыдущие в списке. История загружается после входа/переключения темы и по кнопке «Обновить», включая возврат фокуса на вкладку чата. Старые сообщения и диалоги доступны по кнопке «Показать более ранние…»; загрузка из базы — по 100 записей, отображение — порциями по 40. Ошибки ИИ и индикатор ожидания не записываются как ответы. Неотправленные в облако сообщения остаются в локальной очереди и повторяются при загрузке или обновлении. Гостевая история остаётся отдельно в браузере и автоматически в аккаунт не переносится.

Используется тот же OpenAI-совместимый API и **те же переменные `.env`, что в Classifi**: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `GEMMA_MODEL`. Можно скопировать свой `.env` целиком. Локальная модель не загружается. Ключ читает только Python через существующий `textbook_engine/client.py`; браузер его не получает.

### Проверить локально

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-chat.txt
# Положите .env из Classifi в корень ACEat.
.\start-aceat.cmd
```

Откройте http://127.0.0.1:8000/#chat. Вместо обёртки можно запустить `.venv\Scripts\python.exe server.py`. Обычный `node preview.mjs` показывает статический сайт без локального API.

### Подключить чат на GitHub Pages

Pages раздаёт статические файлы; Python-сервер работает отдельно. Сейчас Pages подключён к локальному серверу автора через временный HTTPS-туннель Cloudflare. При локальном открытии сайта `chat-config.js` выбирает прямое соединение с Python без туннеля.

1. На сервере установите Python 3.10+ и `requirements-chat.txt`, передайте три переменные из Classifi через окружение или серверный `.env`, запустите `python server.py`. Переменная `PORT` задаёт порт и включает прослушивание `0.0.0.0` для хостинга. Без `PORT` сервер доступен только локально.
2. Получите публичный HTTPS-адрес сервера. В `chat-config.js` замените текущий адрес `https://….trycloudflare.com` своим (без `/api/chat`). Это публичный адрес, не ключ.
3. Опубликуйте изменение `chat-config.js` в Pages. Сайт начнёт отправлять вопросы на `POST /api/chat` этого сервера.

Для контейнерного хостинга уже есть `Dockerfile`. Сборка и запуск:

```text
docker build -t aceat .
docker run --rm --env-file .env -p 8000:8000 aceat
```

`.env`, кэш и виртуальное окружение исключены из образа. Домен Pages `https://the-fabulous.github.io` разрешён в CORS; дополнительные origin можно перечислить через запятую в переменной окружения `CHAT_ALLOWED_ORIGINS`. `GET /api/health` проверяет наличие ключа без обращения к модели; ответ модели проверяется настоящим вопросом в чате. Сервер выполняет один граф одновременно, остальные запросы получают сообщение о занятости. Ошибки провайдера не раскрывают ключ или тело его ответа.

### Pages через сервер на ноутбуке

Запустите `start-aceat.cmd`, а затем [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/):

```powershell
.\.local\bin\cloudflared.exe tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:8000
```

Проверенный официальный `cloudflared.exe` установлен локально в игнорируемую `.local/bin/`; в Git его нет. На другой машине его нужно скачать из официальных релизов Cloudflare. Туннель выдаёт HTTPS-адрес `https://….trycloudflare.com`: укажите его в `chat-config.js` и опубликуйте изменение. После каждого перезапуска туннеля адрес будет новым. Для работы чата на Pages ноутбук, Python-сервер, интернет и туннель должны оставаться включёнными. Постоянный адрес требует отдельной настройки именованного туннеля или хостинга. Публичный сервер выдаёт только сайт, подготовленные JSON и API; `.env` не раздаётся.

## Самостоятельный драйвер учебников

### Каталог → книга → предмет → тема → подтема

В сборнике три карточки с обложками и количеством подтем. Внутри каждой книги есть вкладки «Английский», «Математика» и «PDF книги». Существующие 44 главы распределены по 16 тематическим группам в `data/library-structure.json`: например, «Математика → Алгебра → Linear Equations and Inequalities». При чтении раскрыто нужное оглавление, доступны переходы между подтемами и ссылка обратно ко всем темам. Вкладки показывают реальный состав книги; у предметных книг второй предмет остаётся пустым с переходом к сборнику.

Основные адреса: `#book/<id>` (темы основного предмета), `#book/<id>/english`, `#book/<id>/math`, `#book/<id>/math/<глава>` и `#book/<id>/pdf`. Старые ссылки `#book/<id>/<глава>` продолжают открывать тот же материал. Темы и текстовые материалы работают как статические данные на Pages.

В PDF-вкладке доступны «Показать PDF» и «Скачать PDF». Просмотр использует PDF.js, с переходом по страницам, вводом номера и увеличением. Для него и скачивания через ACEat нужен работающий Python-сервер и настроенный HTTPS-туннель. Ссылка на сайт источника также доступна отдельно. Просмотр начинается только после нажатия кнопки; при уходе из книги PDF освобождается. Сервер отдаёт большие файлы частями через HTTP Range и не считывает всю книгу в память для каждой страницы.

`book_source.py` разрешает только три зарегистрированных ID, проверяет SHA-256 по `data/textbook-sources.json`, хранит оригиналы в игнорируемой `.local/sat-sources/` и ограничивает размер скачивания. PDF на сайт и в Git не копируются. Запросы `GET /api/books/<id>/pdf` предназначены для просмотра, `?download=1` возвращает вложение для скачивания. API поддерживает CORS и Range для Pages. Организация библиотеки не запускает генерацию учебников или обращения к ИИ.

Вся логика обработки скопирована внутрь ACEat в `textbook_engine/`. Это самостоятельная копия алгоритмов Classifi: не нужны соседняя папка, API Classifi, загрузка его исходников или LangGraph. Происхождение кода описано в `textbook_engine/ORIGIN.md`.

Драйвер запускается автором вручную и создаёт готовый учебник:

```text
PDF → book_driver.py → textbook_engine/ → data/books/<id>-<хеш>.json
                                      → data/catalog.json
                                      → вкладка «Учебники» → #book/<id>
```

Посетители читают заранее созданные главы. Открытие сборника или учебника не запускает Python, генерацию или запросы к AI. Локальная панель и эндпоинты импорта удалены.

### Три полных PDF в сборнике

Каждый источник скачан целиком и обработан отдельным последовательным запуском существующего `book_driver.py --mode contents`:

| Источник | Страниц PDF | Глав ACEat | Страницы оглавления |
| --- | ---: | ---: | --- |
| Eben Roux — The Complete SAT Mathematics Practice Book | 362 | 11 | 4 |
| Erica L. Meltzer — The Critical Reader, 2nd edition | 358 | 14 | 7–10 |
| Erica L. Meltzer — The Ultimate Guide to SAT Grammar | 441 | 19 | 6–7 |

Драйвер создаёт новые учебные объяснения по темам оглавления. Полные исходные PDF хранятся локально в игнорируемой `.local/sat-sources/`; в читалке есть ссылки на них. Это материалы ACEat, подготовленные с ИИ. Два издания Meltzer относятся к бумажному SAT, что указано в карточках; сведения о формате экзамена в них устарели. Источники, объём, диапазоны оглавления и SHA-256 записаны в `data/textbook-sources.json`.

Режимы драйвера — прежние `contents` и `pages`. Единственная поправка обработки: распознавание номеров глав `1.`, `1:` и чтение колонок оглавления в визуальном порядке. Короткие первоначальные пособия заменены этими тремя страницами.

### Подготовка окружения

Нужен Python 3.10+ и зависимости только этого проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-import.txt
```

Скопируйте `.env.example` в локальный `.env`, добавьте ключ вашего AI-провайдера. Поддерживаются `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `GEMMA_MODEL`; переменные среды имеют приоритет. Драйвер читает только `.env` ACEat, никогда конфигурацию из Classifi. `.env` игнорируется Git. Ключ не передаётся на сайт.

### Создать страницу учебника

Из корня ACEat:

```powershell
.venv\Scripts\python.exe book_driver.py "C:\Books\sat.pdf" --id sat-math --title "SAT Math" --subject math --start-page 2 --end-page 4
```

Или используйте короткую обёртку с теми же аргументами:

```powershell
.\build-book.cmd "C:\Books\sat.pdf" --id sat-math --title "SAT Math" --start-page 2 --end-page 4
```

Дополнительные аргументы: `--author`, `--description`, `--subject math|reading|mixed`, `--mode contents|pages`, `--replace`, `--publish`.

Номера страниц считаются с единицы по порядку в PDF, независимо от печатной нумерации. ID: строчные латинские буквы, цифры и дефисы, начинается с буквы, до 64 символов. Исходный PDF можно хранить вне проекта или внутри игнорируемой папки `.local/`.

- `--mode contents` (по умолчанию): выберите страницы нумерованного оглавления. Драйвер извлечёт главы/подтемы и создаст учебные объяснения по их названиям. Это новые материалы по темам, а не полный текст или точный пересказ книги. Поддерживаются арабская/римская нумерация глав и нумерованные подтемы.
- `--mode pages`: обработка текста выбранных страниц Math, объяснение навыков и новые примеры. Для других направлений используйте оглавление.

Нужен текстовый PDF; OCR сканов не включён. Лимит одного запуска — 500 выбранных страниц; большие фрагменты лучше обрабатывать частями.

Учебник автоматически добавляется в каталог и открывается в читалке с оглавлением, переходами между главами и формулами. При повторном ID драйвер требует `--replace`. Если генерация прервётся, старый каталог сохраняется, а готовые главы остаются в игнорируемом `.local/cache/`. Повторите команду с теми же параметрами для продолжения из кэша. Публикуйте только проверенные материалы, которые разрешено размещать открыто.

### Проверить и опубликовать

```powershell
node preview.mjs
```

Откройте http://127.0.0.1:4173/#textbooks. Внутри вкладки есть раскрываемая инструкция «Как добавить учебник». Читалка использует ссылки `#book/<id>/<номер главы>`.

После проверки повторите команду драйвера с флагом `--publish`. Он зарегистрирует готовый учебник, создаст коммит только каталога и связанных JSON и выполнит `git push origin main` без force. Нужен настроенный Git-доступ к `The-Fabulous/ACEat`. Если уже есть staged-изменения, публикация остановится. Без `--publish` драйвер только подготавливает локальные файлы.

Можно также вручную закоммитить `data/catalog.json` и нужные файлы `data/books/`, затем выполнить push. После сборки GitHub Pages книга появится в публичном сборнике. Оригинальный PDF драйвер на сайт не копирует.

## Данные и совместимость

Во вкладке «Прошлые экзамены» добавлены два [официальных тренировочных варианта College Board](https://satsuite.collegeboard.org/practice/practice-tests/paper): SAT Practice Test 9 и 10, каждый по 56 страниц. Кнопка «Пройти на сайте» открывает интерактивную попытку; отдельные ссылки ведут к объяснениям ответов и инструкции подсчёта баллов. Это неадаптивные бумажные practice tests для Digital SAT, а не архив реально проведённых экзаменов.

### Прохождение вариантов на сайте

Адреса: `#exam/sat-practice-9` и `#exam/sat-practice-10`. В каждом варианте 120 вопросов: два модуля Reading & Writing по 33 и два модуля Math по 27. Доступны ответы A–D, числовой ввод, отметки для повторения, переходы по вопросам и модулям, увеличение страницы и проверка результата. Разные попытки сохраняются локально для каждого варианта и версии данных в этом браузере. «Начать заново» заменяет только текущую попытку выбранного варианта.

Оригинальные страницы отображаются внутри ACEat через PDF.js 6.5.438, по одной странице за раз. Тексты, формулы и рисунки остаются оригинальными; приложение не генерирует задания. Ключи ответов, номера страниц и официальные таблицы диапазонов находятся в `data/exams/`. Числовые ответы принимают эквивалентные дроби и перечисленные в официальном ключе альтернативы. После завершения показываются верные ответы, пропуски, результаты по двум разделам и ориентировочный общий диапазон 400–1600 по таблице именно этого варианта.

Для просмотра заданий нужен запущенный `server.py`, а на Pages — работающий HTTPS-туннель из `chat-config.js`. `GET /api/papers/sat-practice-9` и `…/sat-practice-10` отдают проверенные исходные документы: сервер загружает только эти два фиксированных URL College Board, ограничивает размер и сверяет SHA-256 с метаданными ключей. Исходники кэшируются в игнорируемой `.local/exam-sources/`; в репозитории нет полных PDF и скопированного банка текстов заданий. Проверка ответов выполняется в браузере, без запросов к ИИ. PDF.js загружается с jsDelivr при открытии попытки; при выходе из неё документ и буфер страницы освобождаются.

Чтобы заново подготовить метаданные из этих же официальных файлов, после установки `requirements-import.txt` выполните:

```powershell
.venv\Scripts\python.exe tools\prepare_practice_exams.py
```

Скрипт проверяет наличие всех 240 номеров вопросов, полноту ключей и таблиц баллов. Он не вызывает ИИ и не публикует исходные PDF.

В `data/catalog.json` три независимых массива: `textbooks`, `pastExams`, `challengeExams`. Книги драйвера имеют `id`, `title`, `subject`, `author`, `description`, `source`, `chapter_count`, `book_path`, `url`. Формат JSON `aceat.classifi-book.v1` и маркер `format: classifi` сохранены для совместимости с уже созданными материалами; эти имена не обозначают внешнюю зависимость.

Обычные внешние материалы можно добавлять объектами с `title`, `subject`, `description`, `source` и `url`. Для экзаменов поддерживаются дополнительные `answers_url`, `scoring_url` и `exam_path` (метаданные интерактивного варианта). Допустимы относительные адреса или HTTP(S). Текст выводится безопасно как текст. Формулы учебников обрабатываются MathJax с safe-расширением; при недоступности CDN остаются текстом.

Импорт учебников не меняет архивы экзаменов. ИИ-чат работает независимо от драйвера: он учитывает выбранную тему и историю диалога, но не извлекает текст из учебников автоматически.

## GitHub Pages

**Settings → Pages → Deploy from a branch → main → / (root)**. Сборка приложения не нужна, `.nojekyll` отключает Jekyll. Сайт — статические HTML/CSS/JS и подготовленные JSON. Шрифты загружаются из Google Fonts с системным fallback.

## Проверки

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check app.js
node --check chat.js
node --check chat-config.js
node --check exam.js
node --check library.js
node --test tests/test_exam.mjs
node --test tests/test_library_ui.mjs
node --check preview.mjs
git diff --check
```

Тесты покрывают обработку PDF, обе стратегии генерации, сохранение каталога при ошибках, кэш и замену, защиту публикации. Отдельный тест запускает настоящий `book_driver.py` в изолированной копии ACEat без папки Classifi, с тестовым локальным AI-сервером. Проверки чата выполняют обе ветки настоящего LangGraph с подменёнными ответами модели и HTTP-запросы к тестовому серверу: CORS для Pages, историю, валидацию, занятость, отсутствие ключа и запрет чтения служебных файлов. Экзамены проверяются на полноту 120 вопросов, пустую и безошибочную попытки, официальные диапазоны, дроби и альтернативные числовые ответы, восстановление состояния и валидацию. Для библиотеки проверяется сохранение всех глав в иерархии, предметные вкладки, старые ссылки, неизвестные разделы, Range, скачивание, проверка хешей и защита файлов. Отдельно проверяются фиксированные URL источников, предел размера и PDF-эндпоинты для Pages. Платных AI-запросов и настоящего push тесты не делают.
